# بوفية توب كبدة — Web + Windows Cashier Printing

مشروع طلبات يعمل من المتصفح، مع برنامج Windows صغير للكاشير للطباعة الصامتة والتعرف على الطابعات ومنافذ COM.

## ماذا يفعل؟
- العميل يفتح الموقع من المتصفح على الجوال أو الكمبيوتر.
- عند الضغط على **إرسال الطلب عبر واتساب** يفتح واتساب ويُرسل الطلب، وفي نفس اللحظة يرسل نسخة لبرنامج الكاشير المحلي.
- برنامج الكاشير يطبع الفاتورة مباشرة على طابعة Windows المحددة، بدون نافذة طباعة.
- من شاشة الكاشير يمكن التعرف على طابعات Windows ومنافذ Serial/COM.
- يدعم طابعة الكاشير وطابعة المطبخ.
- التطبيق الأساسي PWA ويمكن تثبيته كتطبيق على Windows/Chrome/Edge عند استضافته عبر HTTPS.

## الملفات
- `app/` موقع العميل والكاشير.
- `print-bridge/` برنامج الطباعة المحلي.
- `firestore.rules` قواعد Firebase (بدون Firebase Storage حتى لا تحتاج Blaze).
- `.github/workflows/windows-installer.yml` يبني مثبت Windows تلقائياً على GitHub Actions.
- `.github/workflows/pages.yml` ينشر الموقع على GitHub Pages.

## تشغيل الموقع
1. ارفع المستودع إلى GitHub.
2. فعّل GitHub Pages من Actions.
3. افتح رابط Pages من المتصفح.
4. استخدم رابط الكاشير بإضافة `#cashier` في نهاية الرابط.

## برنامج الكاشير
من GitHub Actions افتح آخر تشغيل لـ **Build Windows Installer** ثم نزّل artifact باسم `Top-Kabda-Print-Bridge-Windows`.

شغّل:
`Top-Kabda-Print-Bridge-Setup-1.0.0.exe`

المثبت ينشئ اختصاراً على سطح المكتب ويضبط البرنامج ليعمل تلقائياً مع تشغيل Windows.

## إعداد الطابعة
من الكاشير → **الطباعة المباشرة** → **التعرف على الطابعات والمنافذ**.
حدد طابعة الكاشير وطابعة المطبخ ثم نفّذ طباعة تجريبية.

## Firebase
المشروع يستخدم Firestore وAnonymous Auth فقط في النسخة المجانية. لا يحتاج Firebase Storage أو خطة Blaze. طبّق `firestore.rules` كما هو.

## ملاحظة مهمة
الطباعة الصامتة من المتصفح وحده غير مسموحة بشكل عام في Chrome/Edge لأسباب أمنية، لذلك برنامج Print Bridge هو الجزء الذي يتعامل مع طابعات Windows ومنافذ COM.


## التخزين السحابي — Firebase
تم تجهيز الموقع للعمل مع مشروع Firebase:
- **Firestore** لحفظ الطلبات ومزامنتها مباشرة مع الكاشير.
- **Storage** لرفع صور/ملفات القائمة والفواتير عند الحاجة.
- **Anonymous Authentication** لتأمين الوصول بدون حساب للعميل.

### خطوة مطلوبة مرة واحدة من Firebase Console
1. افتح مشروع `keng-972aa`.
2. من Authentication → Sign-in method فعّل **Anonymous**.
3. أنشئ/فعّل Firestore Database.
4. طبّق ملف `firestore.rules`.
5. فعّل Storage وطبّق ملف `storage.rules`.

ملاحظة: إعداد `firebaseConfig` الموجود في الموقع ليس مفتاحاً سرياً. الحماية الفعلية تكون من خلال Authentication وFirestore/Storage Rules. لا تضع Service Account key داخل الموقع.

### الطباعة المباشرة
عند إرسال الطلب:
1. يُحفظ الطلب في Firestore.
2. يُرسل إلى واتساب.
3. يحاول الموقع الوصول إلى **Top Kabda Print Bridge** على الكمبيوتر.
4. يطبع الفاتورة مباشرة على الطابعة المحددة.
5. الكاشير يستمع للطلبات الجديدة من Firestore، لذلك يمكنه استقبال الطلب حتى لو جاء من جهاز/جوال آخر.

الفاتورة الجديدة مصممة للطابعات الحرارية 58mm و80mm، وتشمل بيانات العميل، طريقة ووقت الاستلام، السيارة واللوحة عند اختيار "من السيارة"، الأصناف، الملاحظات، الخصم، الضريبة والإجمالي، مع ضبط عرض الصفحة حتى لا يخرج المحتوى خارج الورق.


## الوضع المجاني

هذا الإصدار لا يعتمد على Firebase Cloud Storage، لأن تفعيله يتطلب حساب فوترة/خطة Blaze.
الطلبات وإعدادات التطبيق محفوظة في Cloud Firestore، وتسجيل الدخول يتم Anonymous. صور الأصناف يتم تصغيرها وضغطها داخل المتصفح ثم حفظها ضمن بيانات التطبيق في Firestore، لذلك لا تحتاج لتفعيل Storage أو إضافة بطاقة.

مهم: Firestore لديه حد لحجم المستند، لذلك النظام يضغط صور القائمة إلى حجم صغير قبل حفظها. إذا كبرت بيانات القائمة جدًا، يفضل تقليل عدد الصور أو نقل الصور لاحقًا إلى خدمة تخزين منفصلة.


## إعداد النسخة النهائية المجانية

1. في Firebase → Authentication → Sign-in method فعّل **Anonymous**.
2. في Firebase → Firestore Database أنشئ قاعدة البيانات إن لم تكن موجودة.
3. افتح Firestore → Rules واستبدل القواعد بملف `firestore.rules` ثم اضغط Publish.
4. **لا تحتاج Firebase Storage ولا تضغط Upgrade project**. الصور تُضغط في المتصفح وتُحفظ داخل بيانات Firestore، وهو مناسب لصور منيو صغيرة.
5. ارفع مجلد `app/` إلى GitHub Pages أو أي استضافة HTTPS.
6. على كمبيوتر الكاشير ثبّت `Top-Kabda-Print-Bridge-Setup-1.0.0.exe` من GitHub Actions وشغّله.
7. افتح الموقع على الكمبيوتر وأضف `#cashier` إلى الرابط، ثم سجّل دخول الكاشير بالرقم السري الموجود في إعدادات الموقع.
8. من الكاشير → الطابعات → التعرف على الطابعات والمنافذ، اختبر طابعة الكاشير والمطبخ.
9. اجعل خيار **قبول وطباعة تلقائية عند قراءة الطلب** مفعّلًا.

### مسار الطلب النهائي
العميل → Firestore → شاشة الكاشير → قبول تلقائي → Print Bridge → طابعة الكاشير + طابعة المطبخ.

إذا كان الكمبيوتر مغلقًا وقت الطلب، سيبقى الطلب في Firestore ويمكن للكاشير استقباله عند فتح الشاشة؛ أما الطباعة فلا يمكن تنفيذها والكمبيوتر/Print Bridge مغلقان.

### تنبيه أمني مهم
النسخة الحالية تستخدم Anonymous Auth حتى تعمل بدون حسابات. لذلك Firestore يقيّد الوصول بالمصادقة لكنه لا يستطيع معرفة أن جلسة معينة هي "كاشير" من Anonymous Auth وحدها. لا تضع بيانات حساسة في الطلبات. إذا أردت فصل صلاحيات العميل عن الكاشير بشكل صارم، نضيف لاحقًا تسجيل دخول للكاشير بحساب Firebase (Email/Password أو Google) ونقفل القراءة/التعديل على الكاشير فقط.
